# Verse v1 plan

Goal: build the Verse v1 meeting assistant so that the speed targets in spec section 6 are met and measured.
Spec: `docs/specs/2026-10-14-verse-meeting-assistant-v1-design.md` (approved by Alex 2026-10-14); critique:
`docs/specs/2026-10-14-speed-critique.md`.
Approach: Phase 0 measures the four unknowns that can change the design (API latency, speech latency, Brave
audio capture, rate limits), with throwaway CLIs. Only after Alex accepts the numbers does Phase 1 build the app
(Swift + Python brain). The Phase 1 packages are fixed in scope and order now; their test cases and thresholds
are finalised from the Phase 0 results.

Global constraints (verbatim from the spec):
- Models: `claude-haiku-5-5` (S/F: effort low, thinking disabled) and `claude-sonnet-5-5` (D: effort medium,
  thinking `between_tools` unless measured otherwise). Prep runs on `claude-sonnet-5-5` at effort high.
- Paid only from the Max monthly API credit: an API key from "Personal API Org", read from the Keychain item
  `verse-anthropic` (account = `$USER`). Never print, log or write the key. No Claude.ai/Max OAuth.
- Python: official `anthropic` SDK ≥ 1.13 (pinned in `requirements.txt`) and `httpx[http2]`. No other LLM
  provider.
- No audio file is ever written. Measurements store numbers only (timings, RMS, transcripts of synthetic test
  audio).
- t = 0 is the acoustic end of the question; every timing is logged per stage.
- No GUI windows during tests (CLI only); kill every process you start, also on failure (memory
  `feedback-gui-test-windows`).
- macOS 26, Xcode 27, Swift 6. No git commits or pushes without the owner's OK.

Packages: Phase 0 = P0-A, P0-B, P0-C, which run in parallel (disjoint folders). Then a gate: Alex reviews
`bench/RESULTS.md`. Phase 1 = P1-1 … P1-6 (order below).

Checklist:

- [x] P0-C Remote-audio capture probe (Brave / Meet)
- [x] Gate: Alex accepts `bench/RESULTS.md` (spec revised if targets are out of reach)

### Package P0-A: API latency and rate limits
Agent: worker-hard
Owns: `bench/api/` (bench_api.py, requirements.txt, README.md, results/*.json), `bench/api/RESULTS_api.md`
Do not touch: `bench/speech/` (P0-B), `bench/audio/` (P0-C)
Read first: spec §5.8 and §6; critique §1 B9–B11 and §3; claude-api skill (Python README, streaming, prompt
caching: pre-warm, TTL, rejected `max_tokens: 0` combinations)

Decisions:
- Use the async client with a custom `httpx.AsyncClient(http2=True, limits=httpx.Limits(keepalive_expiry=300))`.
- Prompt layout per spec §5.8: frozen system → synthetic meeting pack of ~6k tokens (breakpoint 1) → 6
  synthetic finalized turns (breakpoint 2) → the question.
- Output is plain-text lines (`SAY:` / `- `). No structured output.
- Measure from request start to the first text delta (TTFT) and to the first complete `SAY:` line; record the
  server-side `usage` (cache read/write tokens).

Test cases:
- warm_haiku: 30 calls, Haiku, effort low, thinking disabled, cache warm → p50/p90 TTFT; every call after the
  first has `cache_read_input_tokens > 0`.
- cold_haiku: 10 calls after > 6 min idle or with a fresh connection → p50/p90 TTFT and the cold-connection
  delta.
- prewarm: `max_tokens: 0` non-streaming request with the identical tuple → the next real call reads the cache.
- sonnet_between_tools vs sonnet_adaptive: 15 calls each, effort medium → p50/p90 TTFT and to the first point.
- cancel_billing: start a Sonnet stream, close it after the first delta → report `usage.output_tokens` if
  available, and say whether billing stopped (mark unconfirmed if the API gives no evidence).
- rate_limit_headers: read the `anthropic-ratelimit-*` response headers → record the org's limits per model.
- Total spend of the run is printed from `usage` (target < $1).

Acceptance: `cd bench/api && python3 -u bench_api.py --all` → writes `results/api-<timestamp>.json` and prints a
p50/p90 table; the `bench/api/RESULTS_api.md` is filled in from it.
Done means: the table exists for all cases with n as stated, cache reads are proven, and the rate limits are
recorded.
Stop and ask if: the Keychain item `verse-anthropic` is missing or the API returns 401/403 (Alex must create
the key), or spend would exceed $2.

Decisions:

## Phase 1: build

Repo: `~/Desktop/ProjectExamples/CursorExamples/Verse` (private `github.com/FethiOmur/verse`). Commit and push
after each accepted package, with a secret scan first.

Layout:
- `brain/` holds the Python package `verse_brain` (P1-1, P1-2). It needs Python ≥ 3.12 and its own
  `brain/.venv`.
- `app/` holds the Swift package `Verse` (P1-3, P1-4, P1-5): macOS 26, Swift 6.

**Session folder contract** (P1-1 writes it, P1-2 reads it). Path:
`~/Library/Application Support/Verse/sessions/<session-id>/`. All files are UTF-8, and records keep a stable
order: sorted by `id`.

| File | Contents |
|---|---|
| `meta.json` | `{session_id, created_at, prep_note, repos[], languages[], prep_model, prep_usage{input,output,cache_read,cache_write}}` |
| `bank.jsonl` | One `{id:"b001", lang, question, paraphrases:{<lang>:[str]}, opener, points:[str,str,str], deep, sources:[{kind:"prep"\|"vault"\|"commit", ref, quote}]}` per line |
| `facts.jsonl` | `{id:"f001", kind:"number"\|"date"\|"name", text, value, sources:[…]}` |
| `glossary.jsonl` | `{id:"g001", term, line, sources:[…]}` |
| `snippets.jsonl` | `{id:"s001", ref, text, bank_ids:[…]}` |
| `pack.md` | The frozen meeting pack (the cache prefix). Deterministic: the same inputs give byte-identical output |
| `review.md` | The human-readable bank, for Alex to read and correct before the call |

### Package P1-2: Brain runtime
Agent: worker-xhard · Owns: `brain/verse_brain/runtime/**`, `brain/tests/test_runtime*.py` · Do not touch:
`brain/verse_brain/prep/**` (P1-1), `app/**` · Starts after P1-1 is accepted.
Read first: spec §5.1–5.8 and §6.1; `bench/RESULTS.md`; the claude-api skill (streaming, prompt caching,
pre-warm, Sonnet `between_tools`, Haiku `disabled`)
Decisions:
- Process: `python -u -m verse_brain.runtime`, speaking JSON lines on stdin/stdout and logging to stderr. Every
  stdout line is flushed.
- Routes (byte-identical settings tuples, including pre-warm and keep-alive):
  - S/F: `claude-haiku-5-5`, effort low, `thinking:{type:"disabled"}`, max_tokens 120.
  - D: `claude-sonnet-5-5`, effort medium, `thinking:{type:"between_tools"}`, max_tokens 600.
  - Fallbacks: `fallbacks:"default"` on D only (claude-api skill).
- Prompt layout per spec §5.8: system → `pack.md` (breakpoint 1) → finalized turns (breakpoint 2, moved forward at
  most every 4 turns) → the current text.
- **S:** up to 3 calls in flight per turn. Fire when the partial has ≥ 4 new words since the last fire, at least
  300 ms after it, and carries a question cue (supplied by Swift in `partial.cue`).
- **F:** at `turn` if no S call's input is within edit distance ≤ 3 tokens of the endpoint text.
- **D:** fires early when the partial is unchanged for 700 ms and has a cue or a bank hit; otherwise at `turn`.
  Skipped when the `bank_hit` score is ≥ 0.85 and Haiku agrees.
- **Transport:** one warm `DefaultAsyncHttpxClient(http2=True, keepalive_expiry=300)` per model, a
  `count_tokens` ping every 30 s, a hedged duplicate after 1.5 s without a first byte, and `max_retries=0` on
  S/F and 1 on D.
- A token bucket per model at 80 % of the headers' limits.
- Cache keep-alive (`max_tokens: 0`, non-streaming) after 240 s without a call.
Interfaces — Consumes: the session folder contract.
- **Swift → brain:**
  - `{"type":"start","session_dir":str,"lang":"en|it|tr"}`
  - `{"type":"partial","turn_id":str,"speaker":"remote|me","text":str,"cue":bool,"t_audio_end":float}`
  - `{"type":"turn","turn_id":str,"speaker":"remote|me","text":str,"addressee":"me|other|unknown","t_audio_end":float}`
  - `{"type":"bank_hit","turn_id":str,"bank_id":str,"score":float}`
  - `{"type":"control","action":"stop|summarize"}`
- **Brain → Swift:**
  - `{"type":"delta","id":str,"turn_id":str,"tier":"S|F|D","text":str,"line_done":bool}`
  - `{"type":"select","turn_id":str,"id":str}`
  - `{"type":"opener_status","turn_id":str,"ok":bool}`
  - `{"type":"bank_verdict","turn_id":str,"bank_id":str,"agree":bool}`
  - `{"type":"actions","items":[str]}`
  - `{"type":"status","state":"warming|ready|offline|rate_limited|credit_exhausted|refusal|error","message":str}`
  - `{"type":"metric","turn_id":str,"stage":str,"t":float}`
- Model output lines: `SAY: …`, `- …`, `BANK: <id>|none` (S/F), and `OPENER_OK` / `OPENER_WRONG` (first line of D).
Test cases (with a fake streaming client unless marked live):
- `test_layout_cache_stable`: two successive turns → identical prefix bytes up to breakpoint 1, and breakpoint 2
  moves only every 4 turns.
- `test_speculation_policy`: a scripted partial timeline → fires at the expected times, never more than 3 in
  flight, select picks the closest input.
- `test_f_fallback`: no S call close to the endpoint text → exactly one F call at `turn`.
- `test_d_early_and_skip`: a stable partial with a cue → D fires before `turn`; bank score 0.9 + Haiku agrees →
  no D.
- `test_hedge`: a fake first call with no first byte for 2 s → a second call starts at 1.5 s, the first one to
  answer is used, the other is closed.
- `test_opener_wrong`: D's first line `OPENER_WRONG` → an `opener_status ok=false` event is emitted before any D
  text.
- `test_addressee_other`: `addressee:"other"` → no S/F/D calls, and the event is forwarded for display only.
- `test_refusal_and_429`: fake refusal on S → `status refusal`, no retry; 429 on D → one retry after
  `retry-after`.
- `test_stdout_flush`: every emitted line is flushed (pipe read in a subprocess within 50 ms).
- Live (`--live`, budget < $0.30): replay 10 scripted turns against a P1-1 session → per-stage metrics written to
  `brain/tests/out/live-metrics.json`, with cache reads > 0 after the first call.
Acceptance: `cd brain && .venv/bin/python -m pytest tests/test_runtime*.py -q` → all pass; the live run prints
p50/p90 per tier.
Done means: the runtime meets the protocol, the tests pass, and the live metrics are recorded.
Stop and ask if: any settings tuple has to differ between pre-warm and real calls, or live spend would pass $1.

### Package P1-3: Audio capture + transcriber
Agent: worker-xhard · Owns: `app/Package.swift`, `app/Sources/VerseAudio/**`, `app/Sources/VerseSpeech/**`,
`app/Sources/verse-listen/**`, `app/Tests/VerseAudioTests/**`, `app/Tests/VerseSpeechTests/**` · Do not touch:
`brain/**`, `bench/**` (read-only reference)
Read first: spec §5.7 and §6.1; `bench/audio/` (TapProbe: tap by PIDs, aggregate device, TCC checks) and
`bench/speech/` (SpeechTranscriber `.fastResults`, DictationTranscriber `.frequentFinalization`); write new code
in the app, don't import the bench packages
Decisions:
- **Remote audio:** a Core Audio process tap matched by **bundle ID** (macOS 26 `bundleIDs` +
  `processRestoreEnabled`), with the PID-list tap as a fallback. Bundle IDs are configurable; defaults:
  `com.brave.Browser`, `com.brave.Browser.helper`, `us.zoom.xos`, `com.microsoft.teams2`.
- **Mic:** AVAudioEngine with `setVoiceProcessingEnabled(true)` **and the minimum other-audio ducking
  configuration** (voice processing ducks other apps' audio, i.e. the meeting itself; see
  `docs/research-typewhisper-learnings.md` §7). Verify the meeting volume is unchanged; if ducking can't be
  disabled, drop voice processing and rely on the bleed gate. Plus a bleed gate. Mic speech is discarded when
  its 10 ms envelope correlates ≥ 0.6 with the remote envelope at a 0–80 ms lag.
- **Speech engines** behind `protocol TranscriptionEngine`:
  - en/it: `SpeechTranscriber` with `.fastResults`;
  - tr: `DictationTranscriber` with `.frequentFinalization`;
  - a WhisperKit slot left for later.
  - The audio format comes from `bestAvailableAudioFormat`.
- **Dead stream:** exact-zero audio for ≥ 1 s on a running tap → `ListenError.deadStream`. Feed the
  recognizer straight from the tap callback (no 350 ms batching).
- **Permission:** declare `NSAudioCaptureUsageDescription` and `NSMicrophoneUsageDescription`. Report
  `permissionDenied` separately from silence (TCC status + `isRunningOutput`).
- **No audio is ever written to disk.**
Interfaces — Produces:
- `public struct TranscriptEvent: Sendable, Codable { channel: Channel /*.remote|.me*/; text: String; isFinal: Bool;
  audioStart: TimeInterval; audioEnd: TimeInterval; emittedAt: TimeInterval; lang: String }`.
- `public actor ListenSession { init(config: ListenConfig); func start() async throws -> AsyncStream<TranscriptEvent>; func stop() async }`.
- `public struct ListenConfig { lang: String; remoteBundleIDs: [String]; micEnabled: Bool; source: Source /*.live|.file(URL)*/ }`.
  The file source exists only for tests and the replay harness.
- CLI `verse-listen --lang en --seconds 30 [--file path]` prints TranscriptEvents as JSON lines on stdout.
Test cases:
- `testFileSourceEnglish`: a `say -v Samantha` fixture (generated to a temp file at test time, then deleted) →
  volatile events before final events, and the last word appears ≤ 1.0 s after audio end.
- `testTurkishDictation`: a Yelda fixture → events with `lang == "tr"`, finals emitted with frequent
  finalization.
- `testBleedGateDropsEcho`: synthetic remote envelope copied into the mic at a 40 ms lag → no `.me` events.
- `testPermissionDeniedVsSilence`: a mocked TCC denied → `ListenError.permissionDenied`; granted with silence →
  no error and no events.
- `testNoAudioWritten`: run the file source for 5 s while watching the temp and app-support dirs → no new audio
  files.
- Manual live (Alex): `verse-listen --lang en --seconds 30` while Brave plays → remote events stream; speaking
  → `.me` events; on speakers → no false `.me`.
Acceptance: `cd app && swift test --filter 'VerseAudioTests|VerseSpeechTests'` → all pass; `swift build -c release`
builds `verse-listen`.
Done means: live remote + mic transcription works from the CLI with the stated tests passing.
Stop and ask if: the bundle-ID tap API isn't available, a permission prompt can't be triggered from the CLI, or
you find a reason to change the Turkish engine (decided: DictationTranscriber; WhisperKit not on disk, see
